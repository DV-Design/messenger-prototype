# LastCall 0.6.0 review

Date: 2026-10-30. Reviewer: main Codex agent. Scope: changes since 7c440c1,
including core/server encrypted previews, Android Telecom/headless lifetime,
notification routing, recorded media, fullscreen video and adaptive sender caps.
Status: accepted as Android test preview with scoped native evidence and explicit
UI handoff to user; circle/fullscreen physical acceptance remains tracked.

Gates:264tests (54mobile/59server/151core), lint/types/build, Android+iOS JS
exports and native Android release PASS. Chrome9PASS/1explicit TURNskip.

## Findings resolved before release

- Malformed preview JSON could escape directory safeParse through a later outer
  refinement. Added validation short-circuit and malformed/partial-envelope
  regression: invalid input returns failure without throwing.
- Expo58's own registered async NOP headless task ended before LastCall's timers.
  On real cold native QA the preview displayed, but the 9s operation stayed alive.
  LastCall now owns a genuine pending RN task, bounded by a native 12s deadline,
  acquires it before creating JS timers, and releases it in finally. Duplicate
  intents do not renew the deadline. Call runtime ownership is separate.
- Expo BEFORE_CREATE host invalidation could interrupt an active call or a second
  headless task. The app-owned public AppLoader extension delegates loading and
  destruction to Expo, but queues invalidations while call/wake/other RN tasks
  remain active. Checks are main-thread serialized and polling is bounded;
  task-finish events drain the remainder. No dependency source patch.
- Video answer initially used microphone-only foreground service. Explicit video
  answer/outgoing capture now requires granted camera permission and starts the
  camera|microphone|phoneCall service; audio stays microphone|phoneCall and ringing
  stays phoneCall only. Denial fails closed. No app-wide showWhenLocked/unlock.
- Consecutive typed calls and distinct encrypted message previews were suppressed
  by legacy per-recipient 30s cooldown. They now have separate bounded quotas and
  intent deduplication; generic older clients retain compatibility behavior.
- Native recording QA found repeated requests for an already-granted microphone
  opened Android permission activity, producing AppState background and correctly
  cancelling the composer before recording. Permission status is now checked
  before requesting again; real navigation/background cancellation remains.
- Review found paused video could retain stale high-loss/high-RTT receiver
  feedback forever. Feedback now requires advancing outgoing video packets;
  frozen reports are ignored during pause so fresh transport/audio estimates
  can restore video after the existing10s recovery window. Integrated regression
  proves resume and still respects genuinely bad feedback after packets advance.
- Video encoder updates now obtain fresh parameters inside the existing serial
  negotiation queue and validate exact call/track/PC, preserving transaction IDs
  and skipping stale sender work. Unsupported optional caps fall back safely.

## Security and compatibility assessment

Preview uses existing noble X25519-derived pair material with independent HKDF
purpose, random24-byte XChaCha20Poly1305 nonce and authenticated recipient/sender/
kind/intent/expiry. Existing contact pins and sealed conversation membership are
required before display. It is not a ratchet or a new audited identity protocol.
Server migration is additive with explicit messagePreview opt-in defaultfalse;
legacy backgroundSync alone cannot accidentally receive the new encrypted mode.
Text cap800UTF8, envelope3000bytes and totalFCM data4096 are independently bounded.
The service stores no preview/chat mailbox; FCM may queue ciphertext <=60s.

Tap PendingIntents are immutable, app-only, use private random one-time actions,
carry no plaintext, and are checked against a bounded private route ledger.
JS validates server/account scope and restored membership before Router navigation.
Preview does not create chat history or emit a durable content ACK. File notices
carry only the encrypted filename; actual file completion has separate checks.

Recordings use supported Expo58 audio/camera/video modules and the existing
sealed seven-day file outbox. Explicit foreground recording has preview/send/
delete, byte/time bounds and cancellation guards for permissions/read/capture.
Video-circle files retain the full rectangular camera frame; circular cropping
is presentation only and is documented. No background recorder is enabled.

Adaptive video uses native WebRTC congestion control plus upper-bound sender
policy, voice reserve, receiver RTCP feedback, immediate downshift and gradual
recovery. Optional statistics/encoder APIs failing never terminate the call.

## Remaining limits

Physical Android/Russian carrier/voice intelligibility, OEM battery restrictions,
locked video-camera eligibility, iOS/APNs/CallKit and store signing need separate
acceptance. Fullscreen video is in the unlocked/foreground app; the system
Telecom incoming UI handles lockscreen ringing. No instantaneous-delivery, DPI
invisibility or offline-peer availability guarantee. Existing ratchet, transfer
resume/capacity and long background-transfer follow-ups remain tracked.

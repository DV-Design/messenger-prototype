# Субтитры с переводом в звонках

Статус: этап 1, Android 13+. Озвучка по очереди и iOS ещё не сделаны.

## Как работает

1. Человек нажимает «Субтитры». Телефон сообщает об этом собеседнику, но ещё ничего не распознаёт.
2. Собеседник видит запрос и может включить субтитры или отказаться. Распознавание начинается только
   когда включили оба.
3. Телефон говорящего распознаёт речь своего владельца и шлёт текст через data channel звонка.
   Кадры идут в сквозном шифровании (`sealed`), без него субтитры не включаются.
4. Телефон слушающего переводит текст на язык своего владельца и показывает перевод и оригинал.

Слова хранятся только в памяти и исчезают с концом звонка. В историю и журналы они не попадают.

## Что мы взяли из чужого опыта

| Проблема у других | Решение здесь |
| --- | --- |
| На Android `SpeechRecognizer` не работает, пока микрофон занят WebRTC ([форум react-native-webrtc](https://react-native-webrtc.discourse.group/t/speech-to-text-while-calling-with-webrtc/1927)) | Звук берётся из `JavaAudioDeviceModule` и передаётся в распознаватель через `EXTRA_AUDIO_SOURCE`. Распознаватель микрофон не открывает |
| Распознавание чужого голоса на стороне слушателя сложно и хуже по качеству ([разбор WebRTC и SpeechRecognition](https://lilting.ch/en/articles/webrtc-webspeech-realtime-translation)) | Распознаёт телефон говорящего, по сети идёт только текст |
| По документации обычный `createSpeechRecognizer` может отправлять звук на серверы ([SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer)) | Только `createOnDeviceSpeechRecognizer`. Языки, доступные лишь в облаке, считаются недоступными |
| Перезапуск распознавателя после каждой фразы теряет слова | Сегментированная сессия `EXTRA_SEGMENTED_SESSION`. Перезапуск только там, где её нет, и с ограничением при сбоях |
| Модели перевода не скачиваются, приложение молчит ([отзывы о RTranslator](https://discuss.privacyguides.net/t/github-niedev-rtranslator-open-source-real-time-translation-app-for-android/20429)) | Статус скачивания виден на экране. При сбое показываем оригинал |
| Отключённый микрофон продолжает слушаться | В WebRTC выключенный трек не закрывает запись, поэтому при отключённом микрофоне в распознаватель идёт тишина |
| Запись звука блокирует аудиопоток | Поток WebRTC только кладёт данные в очередь на 2 секунды, запись идёт в отдельном потоке |
| Перевод каждого промежуточного результата даёт мерцание и нагрузку | Финальная фраза переводится сразу, промежуточная с паузой 700 мс. Устаревший перевод не заменяет новый |
| Новые кадры ломают старые версии приложения | Возможность объявляется маркером в SDP. Без него кнопки нет и кадры не отправляются |

## Ограничения

- **Android 12 и ниже:** подачи звука из приложения нет, поэтому субтитры выключены.
- **Прошивка без назначенного распознавателя:** на китайской прошивке vivo X200 Ultra (OriginOS 6)
  настройка `config_defaultOnDeviceSpeechRecognitionService` пуста. Тогда приложение напрямую обращается к
  сервису `com.google.android.tts`, проверив его подпись, и только для языков, которые он сам называет
  доступными на устройстве. Проверка на этом телефоне: русский был установлен, фраза из записи распознана без
  активной сети; при включённом интернете счётчики трафика этого сервиса за время распознавания не изменились.
  Счётчики показывают только его собственный трафик, передачу через другой процесс они бы не поймали.
- **Заморозка на vivo:** система подключает распознаватель от своего имени, поэтому приоритет звонка на него не
  распространяется, и оболочка замораживает сервис примерно через 11 секунд (`from fast_freezer`). Приложение
  держит собственное подключение с `BIND_IMPORTANT` на время сессии. Замер на vivo за 36 секунд записи: без него
  текст оборвался на 5,9 секунде; с ним заморозки не было, 3 готовые фразы.
- **Телефон без распознавания на устройстве:** собеседник не увидит слова его владельца, но сам владелец
  субтитры собеседника читать сможет.
- **Google:** языковые пакеты скачиваются у Google. По [описанию ML Kit](https://developers.google.com/ml-kit/android-data-disclosure)
  он также отправляет статистику: задержки, размер текста, названия языков, данные устройства. В описании
  нет сведений об отправке самого текста. Data safety, описание в Play и политика конфиденциальности обновлены 5 ноября 2026: диагностика и идентификаторы указаны с целью «аналитика».
- **Эхо на громкой связи:** если на телефоне нет аппаратного эхоподавления, распознаватель может услышать
  голос собеседника из динамика. Перед озвучкой это нужно замерить.

## Что проверено

Два эмулятора Android 16 (сборка для Google Play с записанной речью), настоящий сервер, настоящий звонок:

| Проверка | Результат |
| --- | --- |
| Английская речь, распознавание на устройстве через звук WebRTC | Фраза распознана без ошибок |
| Русская речь, языковой пакет | Система спросила разрешение на 47 МБ, после него фраза распознана |
| Перевод en→ru, включая первую загрузку модели | Работает, текст показан с оригиналом |
| Задержка от конца фразы до перевода на другом телефоне | Не больше 1,7 с, опрос экрана с шагом около 1,5 с |
| Экран выключен у говорящего | Распознавание продолжается, собеседник видит перевод |
| Один человек включил субтитры | Распознаватель не запускается, у собеседника запрос |
| Микрофон отключён | Слова не распознаются и не отправляются |

Модульные тесты покрывают: согласие, устаревшие кадры, запечатывание шифром, маркер в SDP, разбиение длинных фраз.

**Не проверено:** настоящие телефоны и настоящий микрофон; есть ли распознавание на устройстве на vivo;
эхо на громкой связи; нагрев и расход батареи; качество речи в шуме; звонок с выключенным экраном в глубоком
сне. Размер APK вырос с 54,3 до 70,8 МБ для arm64.

## Этап 2: озвучка по очереди

Пока звучит перевод: в распознаватель идёт тишина, чтобы телефон не слушал сам себя, голос собеседника
приглушён, а собеседник видит, что перевод ещё звучит. Движок: системный `TextToSpeech`.

## Как проверять на эмуляторе

Микрофон эмулятора молчит. Сборка с `LASTCALL_CAPTION_TEST_AUDIO=1` подменяет его файлом
`caption-test.pcm` (16 кГц, моно, 16 бит) из `getExternalFilesDir`. В сборку для Google Play этот флаг не
попадает: `infra/build-android-store.sh` с ним останавливается.

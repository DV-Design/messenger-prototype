# LastCall 0.4.0 — короткие задания

APK: https://lienad.ru/messenger/download/LastCall-0.4.0.apk
Сервер: https://lienad.ru/messenger
Логика доставки и варианты: https://lienad.ru/messenger/architecture.txt

Установите поверх прошлой сборки на двух Android-телефонах. Не удаляйте старое
приложение: его ключ и история хранятся локально. Android 7+, arm64, тестовая
подпись. Expo Go и работающий компьютер не нужны.

## Регистрация и каталог

1. После обновления прежние логин, контакты и история должны сохраниться. На уже
   зарегистрированном устройстве новой анкеты быть не должно.
2. На новой установке системные запросы микрофона, камеры, фото и уведомлений
   должны появиться автоматически перед регистрацией. Их запрашивает ОС по одному;
   отказ от одного не должен блокировать следующие. Телефонная книга не нужна.
   Ранее выданные разрешения ОС повторно не запрашивает.
3. Если устройство ещё не зарегистрировано, укажите имя и уникальный логин. Имя
   может повторяться; логин — 3–24 латинские буквы, цифры и _. Подтверждение идёт
   от сервера. Номер телефона и SMS не используются.
4. Если есть другая новая установка, попробуйте занятый логин: сервер должен
   отказать. После успешной регистрации другой логин тем же ключом не регистрируется.
5. В «Контактах» откройте каталог сервера, обновите его, найдите собеседника по
   @логину и по имени. Проверьте русское имя в другом регистре. Офлайн-профили тоже
   доступны. Участники каталога не добавляются в чаты автоматически.

Ограничение «один логин» относится к защищённому ключу установки, а не к аппаратной
идентификации телефона. После удаления/сброса Android ключ может быть утрачен;
восстановить его по одному публичному логину нельзя.

## Переписка, файл и звонок

1. Оба участника открывают чат друг с другом. Обменяйтесь несколькими сообщениями:
   две галочки должны появляться только после реального получения.
2. Сверните получателя, отправьте текст, затем снова откройте его, пока отправитель
   остаётся в сети. Проверьте получение очереди. **Настоящие push пока не настроены**:
   системное разрешение уведомлений не включает Firebase само по себе.
3. Передайте фото/файл до 5 МиБ. При недоступном получателе приложение ждёт
   соединения до 60 секунд; файл держится только в памяти текущего запуска.
   Перезапуск не восстанавливает передачу файла. После соединения действует
   отдельный таймаут передачи/ACK.
4. Начните звонок недоступному собеседнику и сразу завершите его. После открытия
   получателя звонок не должен стартовать сам. Без подключения ожидание заканчивается
   примерно через 30 секунд. Затем при обоих открытых приложениях проверьте обычный
   аудиозвонок, завершение и обратный звонок.
5. Повторите основную переписку и звонок сначала в одной Wi-Fi сети, затем
   Wi-Fi ↔ мобильная сеть. Публичный резервный TURN ещё не развёрнут: часть NAT
   может не пропускать прямой маршрут.

Сначала выполняется прямая попытка. Через 2,5 секунды без ACK отправляется только
тип ожидания, случайный ID и срок действия. Текст/файл/медиа на сервер не уходят.
При выключенном телефоне или отсутствии сети мгновенная доставка невозможна.
Отправитель должен оставаться доступен; серверной офлайн-почты нет.

FCM/APNs и системные фоновые входящие вызовы требуют отдельной настройки и
испытаний. Эта сборка проверяет управляющую логику, а не доказывает реальную
доставку push. Не используйте текущие результаты как доказательство обхода DPI
или гарантированной связи во всех российских сетях.

## Что прислать

```text
Модели телефонов / Android / операторы:
Сохранился ли профиль после обновления:
Запросы разрешений на новой установке:
Каталог / поиск по логину и имени:
Сообщения при обоих открытых приложениях / после возвращения:
Файл / обычный звонок / отмена ожидающего звонка:
Текст ошибки и действие перед ней:
```

При сбое: Настройки → Диагностика → «Скопировать отчёт о соединении». Не присылайте
ключи устройства или личную переписку. Криптография ещё не прошла независимый
аудит и не использует ratchet. iOS: подписанного IPA/TestFlight пока нет.
